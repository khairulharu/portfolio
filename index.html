How I work

Three habits, each tied to a project below. If a habit does not show up in the work, it does not belong here.

Start from the data model

In the SOS alert backend, a user location is stored once, as a Redis geospatial entry, and the database is only hit when an alert is actually triggered. The shape of the data decides what the rest of the system has to do.

Test the hard part first

Distance, expiry, and filtering are where the SOS feature can quietly go wrong, so the repository and use case tests come before the notification gateway. The gateway starts as a stub that logs its recipients, and the real provider comes later.

Keep the surface small

The e-wallet API is split into clean-architecture layers so a top-up, a transfer, and an email notification can each change without pulling the others apart. Small surfaces are easier to review, and easier to trust.
